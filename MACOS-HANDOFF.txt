Build details
Built on Apple Silicon with Rust 1.98.1 and native JDK 17.0.16.
The app includes the native game, fetch-offline utility, Java engine,
Forge data, a jlink Java runtime, and the browser client.
It is ad-hoc signed, not notarized. macOS may require allowing the
downloaded app under System Settings > Privacy & Security > Open Anyway.

BUILD-MACOS.command downloads a prepared release build kit and requires
GitHub CLI authentication. The CLI was absent on this machine, and an
unauthenticated direct download returned 404, so this build used the
working checkout instead. An authenticated API check later confirmed
that the build kit DOES exist on release v0.3.1.

Source build commands used (from repository root)
    export JAVA_HOME=$(/usr/libexec/java_home -v 17)
    cargo build --release -p arena -p mtg_client --bin mtg-duelstone --bin fetch-offline
    MAVEN_ARGS="-Dmaven.repo.local=$PWD/target/macos-m2" tools/setup-forge.sh
    CARGO_TARGET_DIR=target/macos-web tools/build-web.sh

The default Maven configuration used a corporate mirror that returned
401 for the engine build. An isolated empty Maven settings file was

    mvn -B -s target/macos-maven-settings.xml -gs target/macos-maven-settings.xml -Dmaven.repo.local="$PWD/target/macos-m2" -f engine/pom.xml package

In-game image fix — 2026-10-12 (follow-up)
The published DMG above initially passed download smoke tests, but an actual
match showed blank cards. The user's engine.log recorded Scryfall HTTP 429,
followed by the engine's temporary cooldown errors. The client permanently
cached these failures and never retried them during that session.

Source fix: preserve HTTP status codes, retry temporary image/network failures
using the same texture handle after 60/120/240/300 seconds, and stop after four
retries. Permanent errors (including 404) and decode failures are not retried.
The engine now spaces named-card metadata lookups by 600 ms instead of 120 ms.
Regression coverage checks recovery into the existing handle, no duplicate
retry queue entries, increasing delays, retry limits, and HTTP classification.
The smoke script also checks the normal variant used by in-game cards.
These changes require rebuilding both the native and browser clients and the
Java engine. The release links/checksum above describe the original upload;
a rebuilt local image does not automatically update that GitHub asset.
